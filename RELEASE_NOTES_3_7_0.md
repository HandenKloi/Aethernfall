# Aethernfall 3.7.0

## Цель релиза
3.7.0 — инженерный и gameplay-релиз поверх 3.6.2. Он сохраняет автономную PWA-архитектуру без backend и сборщика, но закрывает найденные проблемы в бою, наградах, сохранениях, физике ресурсов, мобильном UX и обратной связи.

## Исправления боя
- Добавлено окно подготовки ближней атаки врага: 0,32 с у обычных противников и 0,48 с у Стража руин. Первый удар больше не происходит мгновенно при входе в дистанцию.
- Телеграф теперь привязан к реальному `pendingAttack`, а не к приблизительному состоянию cooldown.
- Добавлен input buffer базовой атаки на последние 0,13 с восстановления, чтобы быстрые касания не терялись.
- Добавлено мягкое автонаведение навыков I/II на живую цель в конусе перед игроком при наличии прямой линии.
- Добавлен HUD текущей цели с именем и полосой HP.
- Уклонение сохраняет прежнюю физическую дистанцию 125 единиц за 0,28 с и теперь полезно как реакция на телеграф.

## Выносливость и лечение
- Блок больше не восстанавливает выносливость. Удержание расходует 12 ед./с.
- Пластинчатая броня стража стала защитной side-grade: расход выносливости блока снижен на 30%.
- Блок нельзя начать при запасе выносливости ниже 8; при полном истощении он автоматически сбрасывается.
- «Второе дыхание» больше не тратит 20 выносливости при полном HP.
- «Второе дыхание» получило cooldown 8 с. Атакующие навыки намеренно оставлены без глобального cooldown, чтобы не ломать быстрый темп боя.
- На кнопках уклонения и лечения отображается оставшееся время восстановления.

## Награды и прогресс
- «Знак стража» больше не является RNG-гейтом: при первой победе над Стражем руин он гарантированно создаётся как отдельный лут, пока у игрока нет знака/неподобранного знака.
- Подбор знака больше не переодевает игрока автоматически. Экипировка остаётся осознанным выбором.
- «Осколок пламени», ранее существовавший в данных без источника получения и боевого эффекта, теперь выдаётся за завершение боевого этапа цепочки Пепельных земель.
- Каждый Осколок пламени даёт +3% урона навыков, максимум +15% (5 осколков).

## Навигация и мобильный UX
- На миникарте подсвечивается текущая цель задания: разведчик, нужный ресурс, нужный противник или портал.
- Добавлена настройка для левшей: джойстик и боевые кнопки меняются сторонами, зона управления камерой перестраивается вместе с ними.
- Боевые кнопки получили явные доступные имена (`aria-label`, `title`) и более понятные подписи навыков.
- HUD цели скрывается в очень низком landscape-режиме, чтобы не перекрывать бой.

## Физика и производительность
- Узлы ресурсов больше не являются твёрдыми препятствиями и не блокируют снаряды. Они остаются интерактивными объектами мира.
- Удалена лишняя перестройка spatial buckets при сборе ресурса, поскольку ресурс больше не входит в физические obstacles.
- Ресурсы, создаваемые для восстановления квестовой доступности, проходят relocation сразу при создании.

## Сохранения и PWA
- Добавлена rolling last-known-good копия `aethernfall_save_v30_backup` перед перезаписью валидного основного сохранения.
- При повреждении JSON основного сохранения его точные байты по-прежнему сохраняются в recovery-копию, после чего игра пытается восстановиться из backup, затем legacy-save.
- При успешном восстановлении backup возвращается в primary slot.
- Версии HTML cache-busters, manifest, service worker, art comment и runtime синхронизированы на 3.7.0.
- Добавлена CSP, запрещающая сторонние скрипты, плагины/object и изменение base/form action. Inline CSS-разметка разрешена только потому, что runtime активно обновляет `element.style` для HUD/джойстика.

## Проверки релиза
- 4/4 JavaScript syntax checks (`node --check`).
- 53/53 статических проверки: версии, ссылки на assets, duplicate IDs, CSS parse, manifest, размеры иконок, atlases, service-worker core, PWA/CSP sanity.
- 5/5 тестов физики.
- 5/5 тестов service worker.
- 15/15 gameplay/regression сценариев, включая 2400-кадровый stress loop.

Ограничение среды проверки: локальный Chromium в рабочей среде заблокирован организационной политикой для `file:`/localhost, поэтому реальный browser E2E здесь не выполнен. Поведение DOM/Canvas проверено через тестовый VM-harness; финальная проверка на физическом iOS/Android устройстве остаётся отдельным device-QA этапом.
